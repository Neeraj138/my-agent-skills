# Excalidraw explainers

Make the mechanism clear through specific drawings and visible changes of state. The sketch aesthetic comes from deliberate composition, restrained rough strokes, and human lettering; it does not excuse small diagrams, generic boxes, or unfinished illustration.

## Start from the actual brief

Infer what the conversation already establishes: audience, prior knowledge, topic/source, output, dimensions, duration, pace reference, voice, style, and working folder. Ask only for missing choices that materially change the result. Keep task assets in the requested folder. Reuse existing scripts, audio, and project infrastructure when revising a project.

A still, a silent loop, a narrated short, and a lesson series need different production work. Render only the requested formats and sizes. For a series, divide at conceptual boundaries and give each part an independent question and payoff. Do not force a fixed episode count or length.

Read [story-and-design.md](references/story-and-design.md) before storyboarding. Read [sheets-and-critique.md](references/sheets-and-critique.md) before implementing or reviewing animation. For voiced/video work, also read [production.md](references/production.md).

## Establish the explanation before building

1. Read the supplied source and preserve the transcript or relevant excerpts when useful. Verify uncertain or consequential claims against primary sources. Keep provenance and qualifications in production notes.
2. Write the viewer's opening question and the concrete understanding they should leave with. Introduce prerequisites before using them. A first explanation needs worked examples and time to inspect them; revision material can move faster.
3. Storyboard spoken line or claim → visible state → causal action → resulting state. Include what leaves the frame and how the next shot inherits context. Compute all displayed numerical examples before animating them.
4. Keep one persistent example where it helps continuity. A vector, token, checkpoint, or packet retains its identity and values across shots unless an explicit operation changes it. Make a new illustrative example visibly distinct.

## Build the visual language on sheets first

Start with a few representative frames: a concrete opening, the hardest mechanism, and a consequential transition. Design at the actual output size and inspect at the expected viewing size.

- Give the active operation the foreground. Use context, mechanism close-ups, and an earned system overview rather than one schematic distance throughout.
- Give objects specific internal structure: bound notebook pages, a nonlinear circuit, GPU memory and compute, writable copies of a saved state. Use rectangles when they represent an actual rectangle.
- Use color consistently for concepts. Supporting structure is quieter than active data. Hand-drawn linework remains controlled and numerals remain legible.
- Keep text for names, operands, necessary readouts, and brief explanations the picture cannot supply. Avoid duplicate narration on screen.
- For videos, omit persistent pencils, baselines, badges, headings, decorative particles, and progress steppers unless requested. This is a default for this style, not a reason to strip useful axes, boundaries, or explanatory pointers.

Generate the requested sheets before expensive full renders. Apply a fresh critique to the actual images, then regenerate changed sheets. If the user requests a sheet-first review gate, remain in that phase until its fixes have been applied and reviewed. A pilot pass approves only that pilot, not unreviewed episodes. Use the user's chosen models and division of work; disclose unavailable reviewers instead of silently substituting them.

## Animate the process, then validate the film

Use the existing project engine where practical. Drive visuals from one deterministic clock and actual narration cues. Operands produce results; payloads arrive before accumulators change; signed corrections merge into existing state. Shared-object handoffs preserve continuity. Do not dissolve two complete readable diagrams over one another.

After sheet review, render short proofs of the difficult actions and transitions. Inspect their actual timing and audio before full export. A still cannot certify motion or pacing. Finish with the rendered artifact, a useful cover where requested, and the requested subtitles or source notes. Link the current approved output clearly; label superseded drafts so they cannot be mistaken for it.

Publishing, uploading, paid services, and credentials remain governed by the user's authorization. Creating local video assets does not itself authorize posting them.
