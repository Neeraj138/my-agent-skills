Cost turns linear

Why: up to W tokens nothing changes. Past W, each new token adds a fixed W scores, so total work grows in a straight line. The chart is theory; one reported implementation measured about 2× faster wall-clock (W = 4,096, 16K tokens).

Past W, each token adds a fixed W scores: a line, not a curve.

Why it still sees far: follow the top token down. Each layer it passes through reads a window of the layer below, which already mixed in its own window. After k layers, information can move up to k × W tokens: 32 × 4,096 ≈ 131K, in theory. Toy here: a window of 3 including itself, so each layer adds 2.

Each layer reads a window of the one below. Reach ≈ k × W.

Rolling buffer cache

write

Why: nothing older than W is ever needed, so the KV cache is a fixed array of W slots. Token i writes to slot i mod W, replacing the oldest entry. At 32K tokens this cuts cache memory 8×.

Fixed W slots. Token i overwrites slot i mod W. 8× less memory at 32K.

6

Pre-fill in chunks

cachechunk

Why: a long prompt is known up front, so it is fed in chunks the size of the window. Each chunk attends to itself (causally) and to the cache, then its keys and values take over the cache.

Prompts go in W-sized chunks; each sees itself + the cache.
